# Developer Guidelines & Rules

This project adheres to strict architectural and design constraints to maintain consistency, performance, and visual elegance. All future updates must strictly follow these rules:

## 1. Strictly TypeScript
- **No JavaScript (`.js`, `.jsx`)**: All new files must be written in TypeScript (`.ts`, `.tsx`).
- **Type Safety**: Define robust interfaces and types for all component props, React states, and API responses.
- **Avoid `any`**: Minimize the use of the `any` type. Rely on explicit type declarations wherever possible.

## 2. UI Components: Shadcn UI Exclusive
- **Component Library**: All interactive or foundational UI elements (Buttons, Inputs, Dialogs, Tabs, Cards, Skeletons, etc.) *must* be imported from the local `@/components/ui` directory generated by Shadcn UI.
- **No Competing Libraries**: Do not install or use external component frameworks (e.g., Material UI, Chakra UI, Ant Design).
- **Styling**: Use standard Tailwind CSS strictly for layout, spacing, and typography to position your Shadcn components.

## 3. Dark Mode & Monochrome Aesthetic
- **Zero Colors**: Do not use vibrant Tailwind colors (e.g., `text-red-500`, `bg-blue-600`, gradients). The aesthetic is purely monochrome (black, white, and grays).
- **Semantic Tokens**: Strictly use the semantic Tailwind tokens generated by the theme: `bg-background`, `text-foreground`, `bg-muted`, `border-border`, `bg-primary`, and `text-primary-foreground`.
- **Forced Dark Mode**: The application runs natively in a forced dark-mode environment. You do not need to write explicit `dark:` prefix utility classes; simply assume the default environment is dark.

## 4. Responsive & Compact Design
- **Omni-Device Compatibility**: All layouts must work flawlessly across mobile, tablet, and desktop screens. Use Tailwind's responsive breakpoints (`sm:`, `md:`, `lg:`, `xl:`) effectively.
- **Compact UI Elements**: Keep the UI professional and dense. Avoid excessively massive headers, unnecessarily large icons, or bloated padding. The interface should be data-rich and highly legible on small mobile screens.
- **Avoid Layout Overflow**: Ensure elements like navigation tabs, tables, and long text inputs scale down or wrap correctly on small devices without breaking the viewport width.
